# V1.5.1 构建 2026110402

正式包使用 BUILD_RELEASE.md 列出的 CPython 和定制 PyMuPDF / MuPDF 组合。两端使用各自的 requirements-*-portable.txt。在单独的虚拟环境中构建引擎 wheel 并安装，运行 `python packaging/rebuild/normalize_engine_path.py`，去掉绑定元数据中的构建机目录，再运行 `python -m pip check`、仓库测试和 PyInstaller。

Windows 此次也使用了一条可验证的复用路径。对归档的构建 2026110401 安装器核对 SHA-256 并安装到空目录。在新的 x64 虚拟环境中安装官方 PyMuPDF 1.28.2 和本版依赖，再运行 `python packaging/rebuild/restore_windows_engine.py <旧应用目录>`。脚本核对原生模块哈希，应用由原定制 wheel 对比得到的纯 Python 差异，并更新安装元数据。原始引擎的完整重建入口仍在 BUILD_RELEASE.md。若没有旧安装包，可直接从配套源码重建引擎，使用项目内已生成的 retired_2026110401.iss 编译安装器。

Windows 覆盖安装时仅清理与已知旧文件哈希完全匹配的退出发行文件。核对干净安装、从旧版升级后程序的内置 `--check-install`、主窗口启闭，以及两种安装的私有运行文件是否一致。Mac 将 arm64 应用以其正式名称 Eggie DocuFlow.app 临时签名，将包内符号链接原样保存到 ZIP，再解压检查签名、构建号和成品运行。第三方源码包的 MANIFEST.json 和补充的来源记录列明了各次收集的文件。
