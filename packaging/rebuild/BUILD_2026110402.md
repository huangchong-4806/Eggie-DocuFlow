# V1.5.1 构建 2026110402

正式包使用 BUILD_RELEASE.md 列出的 CPython 和定制 PyMuPDF / MuPDF 组合。两端使用各自的 requirements-*-portable.txt。在单独的虚拟环境中构建引擎 wheel 并安装，运行 `python packaging/rebuild/normalize_engine_path.py`，去掉绑定元数据中的构建机目录，再运行 `python -m pip check`、仓库测试和 PyInstaller。

Windows 此次也使用了一条可验证的复用路径。对归档的构建 2026110401 安装器核对 SHA-256 并安装到空目录。在新的 x64 虚拟环境中安装官方 PyMuPDF 1.28.2 和本版依赖，再运行 `python packaging/rebuild/restore_windows_engine.py <旧应用目录>`。脚本核对原生模块哈希，应用由原定制 wheel 对比得到的纯 Python 差异，并更新安装元数据。原始引擎的完整重建入口仍在 BUILD_RELEASE.md。若没有旧安装包，可直接从配套源码重建引擎，使用项目内已生成的 retired_2026110401.iss 编译安装器。

Windows 覆盖安装时仅清理与已知旧文件哈希完全匹配的退出发行文件。核对干净安装、从旧版升级后程序的内置 `--check-install`、主窗口启闭，以及两种安装的私有运行文件是否一致。Mac 将 arm64 应用以其正式名称 Eggie DocuFlow.app 临时签名，将包内符号链接原样保存到 ZIP，再解压检查签名、构建号和成品运行。第三方源码包的 MANIFEST.json 和补充的来源记录列明了各次收集的文件。

### 重建发布页上的第三方源码 ZIP

用 Python 3.11 或更高版本运行当前维护分支的脚本。下载 [V1.5.0 第三方源码基线](https://github.com/huangchong-4806/Eggie-DocuFlow/releases/download/v1.5.0/EggieDocuFlow_V1.5.0_third-party-sources.zip)，并把 [V1.5.1 正式项目源码](https://github.com/huangchong-4806/Eggie-DocuFlow/releases/download/v1.5.1/EggieDocuFlow_V1.5.1_project-source.zip) 解压到独立目录。以下命令的最后一个路径是解压后包含 `BUILD_RELEASE.md` 的目录。输出文件须尚不存在。

```sh
python packaging/rebuild/assemble_sources.py EggieDocuFlow_V1.5.0_third-party-sources.zip rebuilt.zip cache --project-root EggieDocuFlow_V1.5.1_source
```

`--project-root` 指定要随包收录的项目文件；省略时使用脚本所在项目。正式包的 SHA-256 应与[发布页校验清单](https://github.com/huangchong-4806/Eggie-DocuFlow/releases/download/v1.5.1/SHA256SUMS.txt)一致。

libyuv 的上游归档会重新生成时间戳。对于固定提交 `644251f252a84bf8ce91ff0aca86a9b16b069ab8`，脚本先尝试原始 SHA-256。若不同，则按已验证的发布归档头部还原时间等封装信息，逐项匹配条目、类型、权限和长度，并用刚下载的源码填入内容。只有重新压缩后整个文件的 SHA-256 与原清单完全一致，才写入缓存。随脚本提供的 `libyuv-644251f2.headers.gz` 只保存归档结构，文件正文全部置零。
