# V1.6 第一个纯重构 PR 开发与验收

用户于 2026-11-10 确认《V1.6 统一优化实施方案》并取消云端开发，改在本地执行。本轮只交付第一个纯重构 PR，不启动后续功能 PR，不合入、不发布。

## 起点与保护

- 从 `main` 的 V1.5.2（`73dab5eb895a01dcc905b4e790101da6b6f2de92`，构建 `2026110601`）创建独立干净仓库与 `codex/v1.6-pure-refactor` 分支，不沿用 PR #21、其分支或补丁。
- 原工作目录及既有未提交修改保留。源码基线和 V1.5.2 正式成品保留，测试输出置于独立目录，不覆盖已发布文件。
- 主程序版本字段保持 V1.5.2；1.6.0 版本更新和正式候选包制作属于第 4 个 PR。本轮产生的包仅为隔离验收副本。

## 本轮实现

1. 按页面与职责搬移 `app.py` 的现有方法，窗口入口保留组装与状态初始化。使用正常类方法组织页面与窗口公共职责，不把含无参数 `super()` 的方法搬成类外函数后再挂载。
2. 将现用 `v2` 包改名为 `layout_batch`，同步运行入口、包内引用、测试和当前使用说明。
3. 检查 PyInstaller 实际收集的模块及更新载荷；只处理改名必需的引用和程序文件，不额外清理资源或依赖。
4. 保留各方法既有处理规则、控件、默认值和信号连接。新增公共流程归并、可靠性修复及功能改动不得混入。

## 既定后续范围

本期仍共 4 个 PR：纯重构；可靠性修复与公共流程复用；功能补齐；打包与实测。发票“有代码按代码＋号码、无代码按号码”的查重、xls/CSV 支持与手动导入、来源保护、日志分离、PDF 压缩保护、安全取消和反馈均留在相应后续 PR。重复资源清理、Windows 组件核查和大图片内存优化留在第 4 个 PR，速度、质量及兼容性不得退步，内存优化须以实际收益决定是否保留。

## 验收方式

- 先运行未修改基线的完整测试，保留失败原因与平台跳过项；修改后按相同环境运行完整测试，不能删除测试或放宽断言。
- 对搬移方法作结构对照，核对未变的函数体、默认值与事件连接；实际触发无有效文件的拖入、放下、缩放和关闭分支，覆盖父类调用。
- 检查全部一级页面与 PDF 子工具主流程，保留设置及现有界面。测试设置隔离，避免写入日常偏好。
- 对实际打包产物检查版本、资源路径、模块清单、`--check-install` 和启动。保留定制 PyMuPDF 1.28.2 / MuPDF 1.28.5、Qt Cocoa 修复等既有构建要求。
- 检查全量覆盖和增量载荷中的改名效果及恢复；不以源码测试代替成品或跨平台验收。
- Mac、Windows、自动测试、实际界面和打包验证分别记录。缺少环境的项目标记待验收。完成后复查本 PR，不自动合入或发布。

### 检查中发现的情况

1. 新增拖放测试最初按操作系统字符串比较路径，Windows 的 Qt 返回正斜杠路径。现按 `QUrl.toLocalFile()` 的平台约定检查传给加载函数的完整参数，仍要求只调用一次、事件接受及页面跳转正确；没有改变产品处理逻辑。
2. 首轮 Windows CI 的原有并行打包用例在替换目标安装包时出现一次 `WinError 5`。该构建脚本及原有用例与基线相同；后一次完整 CI 通过，没有删除用例、放宽断言或增加掩盖失败的重试。具体占用来源尚未定位，保留为后续可靠性工作的关注项。
3. Windows 本机首轮测试继承了只应供真实打包使用的发行公钥环境变量，导致原有模拟打包用例要求模拟版本提供构建号，基线和重构均在同一处失败。已将构建变量与测试环境隔离，基线与重构完整复测均通过，不修改产品代码或原有断言。
4. Windows 初始验收脚本等待界面检查 30 分钟后超时，原始报告保留失败状态，不覆写为成功。随后实际完成上述界面检查并退出程序；独立的 `windows-completion.json` 记录补验结果及临时目录清理结果，`windows-retest.json` 与 clean-tests 日志记录有效的完整复测。
